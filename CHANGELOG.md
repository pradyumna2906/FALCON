# Release notes

## 1.0.0 — Academic Project Release

### Delivered application

- Email/password authentication, verification/recovery, owner isolation,
  financial profiles, accounts, debts, transactions and transfers.
- Validated and deduplicated CSV, Excel and digital PDF statement import;
  category suggestions, provenance and explicit user corrections.
- Exact-decimal cash-flow/spending analytics, recurring-payment analysis,
  budget risk, health scores and prioritized insights.
- Forecast candidate selection, uncertainty reporting, constrained multi-goal
  planning, approval history and scenario comparison.
- Grounded conversational assistant with evidence, encrypted history and
  persistent chat; PDF/CSV reports, notifications, export and deletion.
- Responsive React workspace; FastAPI/PostgreSQL backend; production containers,
  explicit migrations, Redis controls, SMTP worker and encrypted recovery tools.

### Release preparation

- Prevent opening the imported-transaction category selector before matching
  categories load; browser coverage explicitly verifies delayed category loading.
- Upgrade pypdf to 6.21.2 to address the 11 advisories found by the fresh
  production audit; retain active-PDF rejection and statement tests.
- Keep browser failure diagnostics available without requiring ripgrep on CI.
- Align backend/frontend versions and generated API metadata with v1.0.0.
- Record owner-reported real-data acceptance without inventing measurements.

### Evidence and limitations

Historical PR evidence reports 2,039 backend unit tests, 49 PostgreSQL/Redis
integration tests, 55 frontend unit tests and 30 browser checks. Refer to the
final commit's GitHub Actions for authoritative results and counts.

The fresh synthetic classification holdout reports 89.04% accuracy and 89.50%
macro-F1. The review artifact remains provisional (`production_eligible=false`)
and cannot automatically assign categories. Independent real-world ML accuracy
has not been measured in the committed evidence.

Synthetic forecasting reports WAPE 8.89%; selected-model aggregate held-out MAE
is 0.42% worse than the comparison baseline. Both nominal 80% and 95% intervals
cover only 69% in that benchmark. These intervals are provisional; WAPE is not
an accuracy percentage or a guarantee of future outcomes.

The 720 assistant replay cases check deterministic expectations, not live LLM
accuracy. Owner-reported successful use with real data is functional acceptance,
not proof of every feature/provider configuration or 100% correctness.
